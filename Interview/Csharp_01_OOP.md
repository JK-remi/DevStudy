# Chapter 1. OOP 개요

## Q1. 객체지향 프로그래밍(Object-Oriented Programming)이란?

- 캡슐화 / 상속 / 다형성 / 추상화

### 답변

객체(Object)를 중심으로 프로그램을 구성하는 프로그래밍 방식입니다.

객체 간의 상호작용을 통해 프로그램을 구성하며, 캡슐화, 상속, 다형성, 추상화를 통해 코드의 재사용성과 유지보수성을 높입니다.

---

## Q2. 절차지향과 객체지향의 차이는?

- Procedure / Object
- 유지보수 / 재사용성

### 답변

절차지향은 수행 순서(Procedure)를 중심으로 프로그램을 구성합니다.

객체지향은 객체(Object)를 중심으로 데이터를 관리하고 객체 간 상호작용을 통해 프로그램을 구성합니다.

객체지향은 캡슐화, 상속, 다형성, 추상화를 통해 유지보수성과 확장성이 뛰어나므로 규모가 큰 프로젝트나 게임 개발에 적합합니다.

### 예상 꼬리 질문

- 게임 개발에서 객체지향이 적합한 이유는 무엇인가?

---

## Q3. Class란 무엇인가?

- 설계도(Field + Method)

### 답변

Class는 객체(Object)를 생성하기 위한 설계도입니다.

객체가 가지는 데이터(Field)와 기능(Method)을 정의합니다.

---

## Q4. Object(객체)란 무엇인가?

- Instance
- Heap

### 답변

Object는 Class를 기반으로 생성된 실제 인스턴스입니다.

Class는 설계도이고, Object는 실제 메모리에 생성되어 동작하는 객체입니다.

---

# Chapter 2. Class & Object

## Q5. new 키워드란?

- 객체 생성
- Heap
- 생성자

### 답변

new는 객체를 생성하는 키워드입니다.

객체를 Heap 메모리에 생성하고 생성자를 호출합니다.

---

## Q6. 생성자(Constructor)란?

- 객체 초기화

### 답변

객체가 생성될 때 한 번 호출되는 특별한 메서드입니다.

객체의 초기값을 설정하는 용도로 사용합니다.

### 예상 꼬리 질문

- 생성자는 여러 개 만들 수 있을까요?
- 생성자에서 virtual 메서드를 호출하면 어떤 문제가 발생할까요?
  - 객체 생성 순서: 메모리 할당 > 부모 생성자 > 자식 생성자 (부모 생성자 실행 시 자식 초기화 안 됨)

---

## Q7. this 키워드는 언제 사용하는가?

- 현재 객체
- 멤버 변수
- this()

### 답변

현재 객체 자신을 가리키는 참조입니다.

주로 멤버 변수와 매개변수의 이름이 같을 때 구분하기 위해 사용합니다.

또한 this()를 통해 같은 클래스의 다른 생성자를 호출할 수 있습니다.

---

## Q8. static이란 무엇인가?

- 정적 메모리
- 객체 공유

### 답변

객체 생성 여부와 관계없이 프로그램 시작 시 메모리에 생성되고 프로그램 종료 시 해제되는 정적 멤버입니다.

객체마다 생성되지 않고 하나만 존재하며 모든 객체가 공유합니다.

---

## Q9. Singleton과 static의 차이는?

### 답변

Singleton은 객체를 하나만 생성하도록 보장하는 디자인 패턴입니다.

static은 객체 생성 여부와 관계없이 메모리에 하나만 존재하는 정적 멤버입니다.

Singleton은 객체이며, static은 C#에서 제공하는 언어 기능이라는 차이가 있습니다.

# Chapter 3. Encapsulation

## Q10. 캡슐화(Encapsulation)란 무엇인가?

- Data 보호
- 접근 제한

### 답변

객체의 내부 데이터를 외부에서 직접 접근하지 못하도록 보호하는 객체지향의 특징입니다.

필요한 기능만 공개하여 데이터의 무결성을 유지합니다.

---

## Q11. 접근 제한자(Access Modifier)의 종류와 차이를 설명해 주세요.

### 핵심 키워드

### 답변

- private : 해당 클래스 내부에서만 접근 가능합니다.
- protected : 해당 클래스를 상속받은 클래스까지 접근 가능합니다.
- public : 어디서든 접근 가능합니다.
- internal : 같은 Assembly 내부에서만 접근 가능합니다.

---

## Q12. Property란 무엇이며 왜 사용하는가?

### 핵심 키워드

- 캡슐화
- Getter / Setter

### 답변

Property는 Getter와 Setter를 통해 멤버 변수에 접근하는 기능입니다.

캡슐화를 유지하면서 데이터를 안전하게 읽고 수정할 수 있습니다.

---

## Q13. Getter와 Setter는 언제 사용하는가?

- Property

### 답변

Getter는 값을 읽을 때 사용합니다.

Setter는 값을 변경할 때 사용합니다.

필요에 따라 Setter를 private으로 두거나 Getter만 구현하여 읽기 전용 Property를 만들 수도 있습니다.

---

## Q14. const와 readonly의 차이는 무엇인가?

- Compile Time
- Runtime

### 답변

const는 컴파일 타임 상수이며 선언과 동시에 초기화해야 합니다.

readonly는 런타임 상수이며 생성자에서 한 번 초기화할 수 있습니다.

# Chapter 4. Inheritance

## Q15. 상속(Inheritance)이란 무엇인가?

- 부모 / 자식
- 재사용

### 답변

기존 클래스의 데이터와 기능을 물려받아 새로운 클래스를 만드는 객체지향의 특징입니다.

공통 기능을 재사용하면서 자식 클래스에서 필요한 기능만 추가하거나 변경할 수 있습니다.

## Q16. 상속을 사용하는 이유는 무엇인가?

- 코드 재사용
- 유지보수

### 답변

공통 기능을 재사용하여 코드 중복을 줄이고 유지보수성을 높이기 위해 사용합니다.

## Q17. base 키워드는 언제 사용하는가?

- 부모 생성자
- 부모 멤버

### 답변

부모 클래스의 생성자나 멤버에 접근할 때 사용합니다.

또한 base()를 통해 부모 생성자를 호출할 수 있습니다.

### 예상 꼬리 질문

## Q18. virtual과 override의 차이는?

### 답변

virtual은 부모 클래스에서 재정의를 허용하는 메서드입니다.

override는 자식 클래스에서 부모의 virtual 또는 abstract 메서드를 재정의하는 키워드입니다.

---

## Q19. sealed 키워드는 무엇인가?

- 상속 제한

### 답변

더 이상 상속되지 않도록 클래스를 제한하는 키워드입니다.

역할이 완전히 확정된 클래스의 추가 상속을 방지할 때 사용합니다.

---

## Q20. new 키워드로 메서드를 재정의하는 것과 override의 차이는 무엇인가?

- 정적 / 동적 바인딩

### 답변

override는 부모 메서드를 재정의하여 다형성을 유지합니다.

new는 부모 메서드를 숨기는 것으로 다형성이 적용되지 않습니다.

# Chapter 5. Polymorphism

## Q21. 다형성(Polymorphism)이란 무엇인가?

### 답변

다형성은 부모 타입 하나로 여러 자식 객체를 동일한 방식으로 사용할 수 있는 객체지향의 특징입니다.

같은 메서드를 호출하더라도 실제 실행되는 동작은 객체의 실제 타입에 따라 달라집니다.

### 예상 꼬리 질문

- 게임에서 다형성을 사용하는 예를 설명해 주세요.

---

## Q22. 다형성을 사용하는 이유는 무엇인가?

- 공통 인터페이스
- 유지보수
- 확장성

### 답변

공통 인터페이스를 유지하면서 객체마다 다른 동작을 수행하기 위해 사용합니다.

부모 타입 하나로 여러 객체를 관리할 수 있어 유지보수성과 확장성이 좋아집니다.

---

## Q23. 업캐스팅(Up Casting)이란 무엇인가?

- 자식 → 부모
- 자동 캐스팅

### 답변

업캐스팅은 자식 객체를 부모 타입으로 참조하는 것입니다.

별도의 형변환 없이 자동으로 수행되며 다형성 구현의 기본 방법입니다.

---

## Q24. 다운캐스팅(Down Casting)이란 무엇인가?

- 부모 → 자식
- 명시적 캐스팅
- is / as

### 답변

다운캐스팅은 부모 타입으로 참조하고 있는 객체를 다시 자식 타입으로 변환하는 것입니다.

명시적인 캐스팅이 필요하며, 실제 객체가 해당 타입인지 확인하기 위해 is 또는 as를 함께 사용하는 것이 좋습니다.

- **is** : 객체가 해당 타입인지 확인하며, 결과를 `bool`로 반환합니다.
```
if (obj is Monster monster)
```
- **as** : 안전하게 형변환을 시도하며, 실패하면 `null`을 반환합니다.
```
Monster monster = obj as Monster;
```

---

## Q25. Interface와 Abstract Class의 차이는 무엇인가?

- 계약 / 기본 구현

### 답변

Interface는 기능의 규약(계약)만 정의하며 여러 개를 구현할 수 있습니다.

Abstract Class는 데이터와 기본 구현을 함께 가질 수 있으며 하나만 상속받을 수 있습니다.

또한 abstract 메서드는 반드시 override하여 구현해야 합니다.

# Chapter 6. Abstraction

## Q26. 추상화(Abstraction)란 무엇인가?

- 공통 기능
- 세부 구현 숨김

### 답변

추상화는 여러 객체의 공통된 기능과 데이터를 하나로 정의하고,

세부 구현은 숨긴 채 필요한 기능만 제공하는 객체지향의 특징입니다.

### 예상 꼬리 질문

- 추상화와 캡슐화의 차이는 무엇인가?

  - 캡슐화: 데이터 보호 (데이터 숨김)

---

### 답변

공통 기능을 하나로 정의하여 코드 중복을 줄이고,

재사용성과 유지보수성을 높이기 위해 사용합니다.
