# 동적 계획법 (Dynamic Programming, DP) 정리

## 1. DP란 무엇인가

DP는 **큰 문제를 작은 부분 문제(subproblem)로 나누고, 그 부분 문제의 답을 저장(메모이제이션)해서 재활용**하는 알고리즘 기법입니다.

핵심 조건 두 가지를 만족해야 DP를 적용할 수 있습니다.

1. **최적 부분 구조 (Optimal Substructure)**
   전체 문제의 최적해가 부분 문제의 최적해들로 구성될 수 있어야 함.
   (예: 최단 경로 문제 — A→C 최단 경로는 A→B 최단 경로 + B→C 최단 경로로 구성됨)

2. **부분 문제의 중복 (Overlapping Subproblems)**
   같은 부분 문제가 여러 번 반복해서 등장해야 함.
   (그렇지 않다면 그냥 분할 정복(Divide & Conquer)이지, DP로 얻을 이득이 없음)

---

## 2. DP 적용 방법 (설계 절차)

### Step 1. 상태(state) 정의
"무엇을 기준으로 부분 문제를 나눌 것인가"를 정합니다.

- 예: `dp[i]` = i번째까지 고려했을 때의 최적값
- 예: `dp[i][j]` = i번째 아이템까지 고려, 특정 조건 j(무게, 개수, 흔적 합 등)를 만족할 때의 최적값

**포인트**: 상태에는 "문제를 재구성하는 데 필요한 최소한의 정보"만 담아야 합니다. 정보가 부족하면 답이 틀리고, 너무 많으면 메모리/시간이 폭발합니다.

### Step 2. 점화식(transition) 세우기
상태 `i`에서 상태 `i+1` (또는 `i-1`)로 어떻게 전이되는지 정의합니다.

- 예: `dp[i] = dp[i-1] + dp[i-2]` (피보나치)
- 예: `dp[i][j] = min(dp[i-1][j], dp[i-1][j-w[i]] + v[i])` (냅색)

전이를 세울 때는 **"이 상태에서 할 수 있는 선택지가 무엇인가"**를 나열하고, 각 선택지가 상태를 어떻게 바꾸는지 적으면 됩니다.

### Step 3. 초기값(base case) 설정
더 이상 쪼갤 수 없는 가장 작은 부분 문제의 답을 미리 정합니다.

- 예: `dp[0] = 0`
- 예: 도달 불가능한 상태는 `INF`로 초기화

### Step 4. 계산 순서 정하기
작은 부분 문제 → 큰 부분 문제 순서로 채워야 합니다 (Bottom-up / 반복문) 또는 재귀 + 메모이제이션(Top-down)으로 구현합니다.

### Step 5. 답 추출
최종 상태(들) 중에서 문제가 원하는 값을 뽑아냅니다.

- 예: `dp[n]`
- 예: `dp[n][k]` 중 최솟값/최댓값
- 예: 조건을 만족하는 상태들 중 최적값

---

## 3. Bottom-up vs Top-down

| 구분 | Bottom-up (반복문) | Top-down (재귀 + 메모이제이션) |
|---|---|---|
| 구현 방식 | 작은 상태부터 배열을 채움 | 재귀 호출하며 이미 계산된 값은 캐시에서 반환 |
| 장점 | 스택 오버플로 위험 없음, 보통 더 빠름 | 필요한 상태만 계산 (불필요한 계산 스킵 가능) |
| 단점 | 계산 순서를 직접 설계해야 함 | 재귀 깊이가 깊으면 스택 오버플로 위험 |
| 적합한 경우 | 모든 상태를 어차피 다 써야 하는 경우 | 상태 공간이 크지만 실제로는 일부만 방문하는 경우 |

---

## 4. DP를 의심해봐야 하는 신호

문제를 읽을 때 아래 키워드/조건이 보이면 DP를 우선 고려합니다.

- "최댓값/최솟값을 구하라", "경우의 수를 구하라"
- "선택/비선택"을 반복하는 구조 (아이템을 고를지 말지, 훔칠지 말지 등)
- 순열/조합으로 완전탐색 시 시간 초과가 날 정도로 `N`이 크지만 (`N! `, `2^N` 등), 그 조합을 **상태 압축**하면 다항식 크기로 줄일 수 있는 경우
- 그리디로 접근했을 때 반례가 존재하는 경우 (지역 최적이 전역 최적을 보장 못 함)
- "누적", "총합이 특정 값 이상/이하" 같은 제약 조건 → 그 값 자체를 상태의 축으로 사용 가능 (냅색류)

---

## 5. 대표 유형과 상태 설계 패턴

| 유형 | 상태 정의 패턴 | 예시 |
|---|---|---|
| 1차원 DP | `dp[i]` = i번째까지의 최적값 | 피보나치, 계단 오르기 |
| 냅색(0/1 Knapsack) | `dp[i][w]` = i번째 물건까지 고려, 무게 제한 w일 때 최적값 | 배낭 문제, 완전범죄 문제 |
| 구간 DP | `dp[i][j]` = 구간 [i,j]에 대한 최적값 | 행렬 곱셈 순서, 팰린드롬 분할 |
| 트리 DP | `dp[node][state]` = 특정 노드를 루트로 하는 서브트리에서의 최적값 | 트리에서 최대 독립집합 |
| 비트마스크 DP | `dp[mask]` = 방문/선택 상태를 비트로 표현 | 외판원 문제(TSP), 순서가 중요한 조합 |
| 경로 DP | `dp[i][j]` = (i,j) 칸까지의 최적값 | 격자 최단경로, LCS |

---

## 6. 실전 팁

1. **완전탐색으로 먼저 정확한 로직을 짠 뒤, 어떤 부분이 중복 계산되는지 찾아서 DP로 전환**하는 순서가 안전합니다.
2. 상태 공간 크기를 항상 계산해보세요. `상태 개수 × 전이 비용`이 시간 제한 안에 들어오는지 확인.
3. "값의 범위 제약(n, m 같은 한계값)"이 있다면, 그 값을 상태의 축으로 삼을 수 있는지 검토하세요 — 특히 "총합이 특정 값 미만/이상"이라는 조건은 그 값을 캡(cap)해서 상태 크기를 줄이는 트릭으로 자주 쓰입니다.
4. 메모리가 부족하면 **1차원으로 롤링(rolling array)** 해서 최적화할 수 있습니다 (단, 갱신 순서에 주의 — 0/1 냅색은 뒤에서부터 갱신).
5. 점화식을 세울 때 "선택지 나열 → 각 선택지의 비용/효과"를 표로 그려보면 실수를 줄일 수 있습니다.
