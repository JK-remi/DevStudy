# 최단 경로 알고리즘 정리: Dijkstra, Bellman-Ford, SPFA

## 0. 공통 개념: 완화(Relaxation)

간선 `u → v`(비용 `w`)에 대해 "u를 거쳐 가면 v까지 더 싸게 갈 수 있는가?"를 확인하고, 그렇다면 갱신합니다.

```cpp
if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;
```

세 알고리즘 모두 이 완화를 어떤 **순서**로, 몇 번 하느냐만 다릅니다.

- 초기화: `dist[시작] = 0`, 나머지는 무한대(INF)
- 완화 조건에서 바뀔 수 있는 값은 `dist[u]`뿐입니다. `w`는 고정입니다.

---

## 1. 왜 "BFS + 방문 배열"은 틀리는가

BFS는 **간선 수** 기준으로 가까운 노드를 먼저 방문합니다. 가중치 그래프에서는 **비용** 기준으로 가까운 노드가 먼저 확정되어야 하는데, 그렇지 않기 때문에 처음 도달한 비용을 확정하면 틀릴 수 있습니다.

```
N=4, K=10
road = [[1,2,10],[1,3,1],[3,2,1],[2,4,1]]
```

- 정답: 1→3→2→4, 각 마을까지 비용 0, 2, 1, 3 → 모두 K 이내이므로 4개
- BFS + `vis`: 1에서 2를 비용 10으로 먼저 방문 처리 → 이후 더 싼 경로(비용 2)는 무시 → 2에서 4까지 11이 되어 K 초과 → 3을 반환 (오답)

해결 방법은 `vis`를 "방문 여부"가 아니라 **"지금까지 찾은 최소 비용(`dist`)"** 으로 바꾸고, 더 싼 경로를 찾을 때마다 갱신하는 것입니다.

---

## 2. Bellman-Ford

**한 줄 요약:** 모든 간선을 V-1번 반복해서 완화하는 알고리즘

### 동작 원리

1. `dist[시작] = 0`, 나머지는 INF
2. 모든 간선에 대해 완화를 한 번씩 수행 (= 1라운드)
3. 라운드를 **V-1번** 반복

**V-1번이면 충분한 이유:** 최단 경로는 같은 노드를 두 번 지나지 않으므로 간선이 최대 V-1개입니다. k번째 라운드가 끝나면 "간선 k개 이하로 가는 최단 거리"가 확정됩니다.

```cpp
for (int i = 0; i < V - 1; i++)
    for (auto& [u, v, w] : edges)
        if (dist[u] != INF && dist[u] + w < dist[v])
            dist[v] = dist[u] + w;
```

### 특징

- 시간복잡도 **O(V·E)**
- **음수 간선 가능**
- V번째 라운드에서도 갱신이 일어나면 **음수 사이클** 존재 → 감지 가능
- 단점: 매 라운드 모든 간선을 훑기 때문에 낭비가 큼

## 3. SPFA (Shortest Path Faster Algorithm)

**한 줄 요약:** Bellman-Ford를 **큐**로 최적화한 버전

### 아이디어

간선 `u → v`의 완화 조건 `dist[u] + w < dist[v]`에서 바뀔 수 있는 값은 `dist[u]`뿐입니다. 따라서 이 간선이 새로 완화에 성공하려면 `dist[u]`가 이전보다 **줄어들었어야** 합니다.

그래서 `dist`가 방금 줄어든 노드만 큐에 넣고, 그 노드에서 나가는 간선만 확인합니다.

### 예시

```
1 → 2 (5),  1 → 3 (1),  3 → 2 (1),  2 → 4 (1)
```

1. `dist[1]=0` → 1의 간선 확인: `dist[2]=5`, `dist[3]=1` (갱신된 노드: 2, 3)
2. 노드 3의 간선 `3→2`: `1+1=2 < 5` → `dist[2]=2`로 다시 감소
3. 노드 2의 간선 `2→4`: `dist[4]=3`

노드 1은 `dist[1]`이 그대로라 다시 볼 필요가 없고, 노드 2는 `dist[2]`가 5에서 2로 줄었으므로 간선을 다시 확인해야 합니다.

### 코드

```cpp
queue<int> q;
dist[start] = 0;
q.push(start);

while (!q.empty()) {
    int u = q.front(); q.pop();
    for (auto [v, w] : adj[u]) {
        if (dist[v] > dist[u] + w) {   // 완화 성공
            dist[v] = dist[u] + w;
            q.push(v);                  // 줄어든 노드만 재탐색
        }
    }
}
```

### 특징

- 평균적으로 O(E) 근처, **최악 O(V·E)** (Bellman-Ford와 동일)
- 음수 간선 가능
- 같은 노드가 큐에 여러 번 들어갈 수 있음
- 음수 사이클 감지: 한 노드의 큐 삽입 횟수가 V 이상이면 사이클 존재
- 조건은 `<=`로 건너뛰어야 합니다 (`dist[v] <= t`이면 continue). 동일 비용 재삽입이 전파되어 큐가 불필요하게 커지는 것을 막기 위해서입니다.

## 4. Dijkstra

**한 줄 요약:** 아직 확정되지 않은 노드 중 **가장 가까운 노드부터** 확정하며 완화하는 알고리즘

### 핵심 아이디어

음수 간선이 없다면, 현재 `dist`가 가장 작은 노드는 이후에 더 싼 경로가 나올 수 없습니다. 따라서 그 노드의 거리는 확정이고, 한 번 확정된 노드는 다시 볼 필요가 없습니다.

### 동작 원리

1. `dist[시작] = 0`, 우선순위 큐에 `{0, 시작}` 삽입
2. 큐에서 `dist`가 가장 작은 노드 `s`를 꺼냄
3. 이미 더 작은 값으로 처리된 노드(`c > dist[s]`)면 건너뜀
4. `s`의 인접 노드에 대해 완화, 성공하면 우선순위 큐에 삽입
5. 큐가 빌 때까지 반복

### 코드 (프로그래머스 12978 배달)

```cpp
#include <vector>
#include <queue>
using namespace std;

int solution(int N, vector<vector<int>> road, int K) {
    vector<vector<pair<int,int>>> adj(N + 1);   // {도착, 비용}
    for (auto& r : road) {
        adj[r[0]].push_back({r[1], r[2]});
        adj[r[1]].push_back({r[0], r[2]});
    }

    vector<int> dist(N + 1, 1e9);
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq; // {비용, 노드}
    dist[1] = 0;
    pq.push({0, 1});

    while (!pq.empty()) {
        auto [c, s] = pq.top(); pq.pop();
        if (c > dist[s]) continue;
        for (auto [e, w] : adj[s]) {
            if (dist[e] > c + w) {
                dist[e] = c + w;
                pq.push({dist[e], e});
            }
        }
    }

    int answer = 0;
    for (int i = 1; i <= N; i++) if (dist[i] <= K) answer++;
    return answer;
}
```

### 특징

- 시간복잡도 **O(E log V)** (우선순위 큐 사용 시)
- **음수 간선 불가** (가장 가까운 노드가 확정이라는 가정이 깨짐)
- 중복 도로는 인접 리스트에 그대로 넣어도 다익스트라가 알아서 최소를 선택

---

## 5. 한눈에 비교

| | Dijkstra | Bellman-Ford | SPFA |
|---|---|---|---|
| 방식 | 우선순위 큐, 가까운 노드부터 확정 | 모든 간선 V-1번 반복 | 큐, 줄어든 노드만 재탐색 |
| 시간복잡도 | O(E log V) | O(V·E) | 평균 ~O(E), 최악 O(V·E) |
| 음수 간선 | 불가 | 가능 | 가능 |
| 음수 사이클 감지 | 불가 | 가능 (V번째 라운드 갱신 여부) | 가능 (노드별 큐 삽입 횟수 카운트) |
| 구현 난이도 | 보통 | 쉬움 | 쉬움 |
| 최악 케이스 위험 | 없음 | 항상 느림 | 특정 입력에서 느려질 수 있음 |

## 6. 언제 무엇을 쓰나

- **음수 간선 없음** → Dijkstra (기본 선택, 가장 안전)
- **음수 간선 있음** → Bellman-Ford 또는 SPFA
- **음수 사이클 감지가 필요** → Bellman-Ford
- **모든 쌍 최단 거리 + N이 작음** → Floyd-Warshall O(N³) (프로그래머스 12978처럼 N ≤ 50이면 구현이 가장 짧음)
- 코딩테스트에서 SPFA는 짧게 짤 수 있어 편하지만, 최악 케이스가 있으므로 음수 간선이 없다면 Dijkstra가 더 안전합니다.
