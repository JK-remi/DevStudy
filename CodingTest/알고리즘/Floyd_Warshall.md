# Floyd-Warshall 패턴 정리

## 1. 기본 개념

Floyd-Warshall은 **모든 정점 쌍(all-pairs)** 사이의 관계(최단거리, 도달 가능성 등)를 구하는 알고리즘입니다. 핵심 아이디어는 단 하나입니다.

> "정점 k를 **경유**해서 i에서 j로 가는 게 더 나은가?"
> 를 모든 k에 대해, 모든 (i, j) 쌍에 대해 확인한다.

```cpp
for (int k = 1; k <= n; k++)
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            // i -> k -> j 를 고려해서 i -> j 갱신
```

**루프 순서가 반드시 k → i → j** 여야 합니다 (이유는 아래 "왜 이 순서인가" 참고).

---

## 2. 왜 동작하는가 (귀납적 증명 아이디어)

k 라운드가 끝난 시점에서 다음이 성립하도록 설계되어 있습니다:

> **k번째 라운드 종료 시점**: `dist[i][j]` (또는 `reach[i][j]`)는
> "중간 경유 노드가 모두 `{1, 2, ..., k}` 안에 있는 i→j 경로들" 중 최선의 값을 담고 있다.

- **k=0 (초기 상태)**: 중간 경유 노드 없이, 직접 간선만 반영된 상태.
- **k 라운드**: k=1..n을 하나씩 열어가면서, "이제 k도 경유지로 써도 된다"는 조건 하에 `i→k→j` 조합을 검사.
- **k=n까지 완료**: 경유 노드 제한이 사라짐 → 전체 그래프에서의 진짜 최단거리/도달 가능성 완성.

이게 바로 **경로 길이(hop 수)에 상관없이 항상 정확한 이유**입니다. 3-hop이든 100-hop이든, 그 경로의 중간 노드들이 각각 어느 시점의 k에서 열리느냐에 따라 순차적으로 누적 반영됩니다.

### 왜 루프 순서가 k-i-j여야 하는가

`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`에서 우변의 `dist[i][k]`, `dist[k][j]`가 **"k를 경유하지 않는" 이전 라운드의 값**이어야 정확합니다. k를 가장 바깥 루프로 두면, i,j 루프를 도는 동안 `dist[i][k]`와 `dist[k][j]`는 아직 이번 k 라운드에서 갱신되지 않은 상태(= k-1까지만 경유 허용된 값)로 고정되어 있어 이 조건이 자동으로 만족됩니다. i나 j를 바깥에 두면 이 보장이 깨져서 틀린 답이 나올 수 있습니다.

## 3. 시간/공간 복잡도

| 항목 | 복잡도 |
|---|---|
| 시간 | O(n³) |
| 공간 | O(n²) |

- n ≤ 400~500 정도면 안전하게 사용 가능 (10^8~10^9 근처 연산)
- n이 크면(1000 이상) 부적합 → BFS/다익스트라 등으로 전환 고려

## 4. 대표 변형 3가지

### (1) 최단 거리 (가중치 그래프)

```cpp
vector<vector<long long>> dist(n+1, vector<long long>(n+1, INF));
for (int i = 1; i <= n; i++) dist[i][i] = 0;
for (auto& e : edges) dist[e.u][e.v] = min(dist[e.u][e.v], (long long)e.w);

for (int k = 1; k <= n; k++)
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            if (dist[i][k] < INF && dist[k][j] < INF)
                dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]);
```
- `dist[i][k] + dist[k][j]`가 INF끼리 더해져 오버플로우 나지 않도록 조건 체크 필수.

### (2) 도달 가능성 / 전이적 폐쇄 (Transitive Closure) — 이번에 다룬 문제 유형

```cpp
vector<vector<bool>> reach(n+1, vector<bool>(n+1, false));
for (auto& e : edges) reach[e.u][e.v] = true;

for (int k = 1; k <= n; k++)
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            if (reach[i][k] && reach[k][j])
                reach[i][j] = true;
```
- 가중치가 없고 "도달 가능한가/아닌가"만 필요할 때. `bool` 대신 `dist`를 써도 되지만(0/INF), bool이 더 직관적이고 빠름.

### (3) 경로 존재 + 카운팅/부울 조합 (예: 최소 환 찾기, 음수 사이클 탐지 등)

```cpp
// 음수 사이클 탐지: k=n까지 다 돈 후 dist[i][i] < 0 이면 음수 사이클 존재
for (int i = 1; i <= n; i++)
    if (dist[i][i] < 0) { /* negative cycle */ }
```

## 5. BFS/DFS 방식과의 비교 (일반론)

| 기준 | Floyd-Warshall | 노드별 BFS/DFS (n번 반복) |
|---|---|---|
| 시간복잡도 | O(n³) | O(n × (V+E)) — 그래프가 희소하면 더 빠를 수 있음 |
| 구현 난이도 | 매우 낮음 (3중 루프 고정 패턴) | 상대적으로 높음 (방문 배열, 큐/스택 관리) |
| 적합한 그래프 | n이 작고 촘촘한(dense) 그래프 | n이 크고 희소한(sparse) 그래프 |
| 코드 실수 가능성 | 낮음 | 조건문·경로 추적 로직에서 실수 잦음 |

**경험적 기준**: n ≤ 500 정도이고 "모든 쌍" 정보가 필요하면 Floyd-Warshall이 구현 속도·안정성 면에서 우선 고려 대상입니다.

## 6. 문제 유형 시그널 (언제 Floyd-Warshall을 떠올릴지)

다음 키워드/조건이 보이면 후보로 고려:

- "**모든 쌍**의 최단거리/도달 가능성을 구하라"
- "A가 B를 이겼다/알고 있다/전달 가능하다" 같은 **전이적 관계**의 완성 (i→k, k→j 이면 i→j)
- n이 **작다** (몇백 이하) — 이게 가장 중요한 시그널
- "경유해서"라는 표현이 문제에 직접 등장하거나, 관계의 합성(composition)이 필요할 때

이번 순위 추론 문제(49191)의 경우 "A가 B를 이기고 B가 C를 이기면 A는 C를 이긴 것으로 간주"라는 조건이 정확히 전이적 폐쇄 패턴에 해당했습니다.

## 7. 흔한 실수 포인트

1. **루프 순서를 i-j-k로 잘못 짜는 것** → k를 반드시 최외곽에 둘 것.
2. 초기화 시 `dist[i][i] = 0` 빠뜨리기 (최단거리 버전에서).
3. INF끼리 더해서 오버플로우/음수 wrap-around 발생 (조건 체크 없이 `dist[i][k]+dist[k][j]` 계산).
4. n이 큰데(예: 10^4 이상) 무작정 적용해서 시간초과.
