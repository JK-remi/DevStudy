    - 01시 30분 59초 부터 01시 37분 44초 까지 : 4번, 1번 재생 기록이 두차례 있으므로 재생시간의 합은 00시간 06분 45초 X 2 = 00시간 13분 30초
    - 01시 37분 44초 부터 01시 45분 14초 까지 : 4번, 1번, 5번 재생 기록이 세차례 있으므로 재생시간의 합은 00시간 07분 30초 X 3 = 00시간 22분 30초
    - 따라서, 이 구간 시청자들의 누적 재생시간은 00시간 13분 30초 + 00시간 22분 30초 = 00시간 36분 00초입니다.
    
## 문제
"죠르디"의 동영상 재생시간 길이 play_time, 공익광고의 재생시간 길이 adv_time, 시청자들이 해당 동영상을 재생했던 구간 정보 logs가 매개변수로 주어질 때, 시청자들의 누적 재생시간이 가장 많이 나오는 곳에 공익광고를 삽입하려고 합니다. 이때, 공익광고가 들어갈 시작 시각을 구해서 return 하도록 solution 함수를 완성해주세요. 만약, 시청자들의 누적 재생시간이 가장 많은 곳이 여러 곳이라면, 그 중에서 가장 빠른 시작 시각을 return 하도록 합니다.

## 제한사항
- play_time, adv_time은 길이 8로 고정된 문자열입니다.
  - play_time, adv_time은 HH:MM:SS 형식이며, 00:00:01 이상 99:59:59 이하입니다.
  - 즉, 동영상 재생시간과 공익광고 재생시간은 00시간 00분 01초 이상 99시간 59분 59초 이하입니다.
  - 공익광고 재생시간은 동영상 재생시간보다 짧거나 같게 주어집니다.
- logs는 크기가 1 이상 300,000 이하인 문자열 배열입니다.
  - logs 배열의 각 원소는 시청자의 재생 구간을 나타냅니다.
  - logs 배열의 각 원소는 길이가 17로 고정된 문자열입니다.
  - logs 배열의 각 원소는 H1:M1:S1-H2:M2:S2 형식입니다.
    - H1:M1:S1은 동영상이 시작된 시각, H2:M2:S2는 동영상이 종료된 시각을 나타냅니다.
    - H1:M1:S1는 H2:M2:S2보다 1초 이상 이전 시각으로 주어집니다.
    - H1:M1:S1와 H2:M2:S2는 play_time 이내의 시각입니다.
- 시간을 나타내는 HH, H1, H2의 범위는 00~99, 분을 나타내는 MM, M1, M2의 범위는 00~59, 초를 나타내는 SS, S1, S2의 범위는 00~59까지 사용됩니다. 잘못된 시각은 입력으로 주어지지 않습니다. (예: 04:60:24, 11:12:78, 123:12:45 등)
- return 값의 형식
  - 공익광고를 삽입할 시각을 HH:MM:SS 형식의 8자리 문자열로 반환합니다.

## ver1. 로그 시작/종료 시점 기준 후보 구간 완전탐색  
```c++
const int HH=60*60, MM=60;
int time(const string &t)
{
    int r=0;
    for(int i=0, s=HH; s>0; i+=3, s/=MM)
        r+=stoi(t.substr(i))*s;
    return r;
}

pair<int,int> log(const string &t)
{
    return pair<int,int> ({time(t),time(t.substr(9))});
}

string solution(string play_time, string adv_time, vector<string> logs) {
    // 재생 구간 기록, 최다 시청 구간, 동시 재생
    const int S=logs.size();
    
    const int pt=time(play_time);
    const int at=time(adv_time);
    if(pt==at) return "00:00:00";
    
    vector<pair<int,int>> v(S);
    for(int i=0;i<S;i++)
        v[i]=log(logs[i]);
    
    int ans=0, time=0;
    for(int i=0, cf,sf,ef, cb,sb,eb; i<S; i++)
    {
        sf=v[i].first, ef=sf+at;
        if(ef>pt) ef=pt, sf=pt-at;
        
        eb=v[i].second, sb=eb-at;
        if(sb<0) sb=0, eb=at;
        
        cf=0, cb=0;
        for(int j=0; j<S; j++)
        {
            if(v[j].first<=ef && v[j].second>=sf)
                cf+=min(ef,v[j].second)-max(sf,v[j].first);
            if(v[j].first<=eb && v[j].second>=sb)
                cb+=min(eb,v[j].second)-max(sb,v[j].first);
        }
        
        if(cf>time || (cf==time&&sf<ans)) ans=sf, time=cf;
        if(cb>time || (cb==time&&sb<ans)) ans=sb, time=cb;
    }
    
    string answer = "";
    for(int s=HH; s>0; ans%=s, s/=MM)
    {
        string tmp=to_string(ans/s);
        if(tmp.length()<2) tmp='0'+tmp;
        
        answer=answer+tmp;
        if(s>1) answer+=':';
    }
    return answer;
}
```
### 시간복잡도
- O(S^2)
  - 후보 2S개 * 로그 S개 순회

### 동작 원리
- 각 로그마다 후보 광고 구간 두 개를 만듭니다. 하나는 로그 시작에 광고 시작을 맞춘 구간이고, 다른 하나는 로그 종료에 광고 끝을 맞춘 구간입니다. 재생시간을 벗어나면 \[pt-at,pt] or \[0,at]로 보정
- 후보마다 모든 로그를 순회하며 광고구간과 겹치는 시간을 더함
- 겹친 시간이 가장 큰 후보를 고르고, 같으면 시작 시간이 이른 쪽을 고름 

### 문제점
- 시간 초과

## ver+. 차이 배열(imos) + 2중 누적합 + 슬라이딩구간 비교 
```c++
const int HH=60*60, MM=60;
int time(const string &t)
{
    int r=0;
    for(int i=0, s=HH; s>0; i+=3, s/=MM)
        r+=stoi(t.substr(i))*s;
    return r;
}

string solution(string play_time, string adv_time, vector<string> logs) {
    const int S=logs.size();
    
    const int pt=time(play_time);
    const int at=time(adv_time);
    if(pt==at) return "00:00:00";
    
    vector<int> v(pt+1,0);
    for(int i=0;i<S;i++)
        v[time(logs[i])]++, v[time(logs[i].substr(9))]--;
    
    vector<long long> cnt(pt+1,0);
    for(int i=0, n=0; i<pt; i++)
        n+=v[i], cnt[i+1]=cnt[i]+n;
    
    long long a=0, t=0, tmp;
    for(int i=0; i<=pt-at; i++)
    {
        tmp=cnt[i+at]-cnt[i];
        if(tmp>t) t=tmp, a=i;
    }
    
    string answer = "";
    for(int s=HH; s>0; a%=s, s/=MM)
    {
        string str=to_string(a/s);
        if(str.length()<2) str='0'+str;
        
        answer=answer+str;
        if(s>1) answer+=':';
    }
    return answer;
}
```
### 시간복잡도
- O(S+pt) (pt = 최대 360,000)

### 동작 원리
- 로그 시작 초에 v\[start]++, 종료 초에 v\[end]-- 삽입
- v를 누적하면 각 초의 동시 시청자 수 n이 나옴
- n을 다시 누적해 cnt\[i](i초 직전까지의 총 누적 시청 시간)을 만듦
- 시작 시각 i를 0부터 pt-at까지 훑으면서 구간 \[i, i+at)의 합 cnt\[i+at]-cnt\[i]를 구함
- \> 로 갱신하므로 최댓값이 같을 때 가장 이른 시작 시각이 남음
- 결과를 HH:MM:SS 로 포맷해 반환

## 참고
### imos
imos법은 구간에 값을 더하는 작업을 O(1)로 처리하고, 마지막에 한 번 누적해서 결과를 얻는 기법입니다. 차이 배열(difference array)과 같은 아이디어이고, 일본 알고리즘 커뮤니티에서 imos(いもす)라는 이름으로 널리 퍼졌습니다.

- 핵심 아이디어
구간 [l, r)에 +1을 하고 싶으면 배열 전체를 순회하지 않고 d[l]++, d[r]-- 두 곳만 바꿉니다.
모든 구간을 이렇게 기록한 뒤 d를 앞에서부터 누적합하면, 각 위치에 몇 개의 구간이 겹치는지가 나옵니다.

- 예시
구간 [1,4), [2,5)를 기록하면 길이 6의 배열은 다음과 같습니다.

기록: d = \[0, +1, +1, 0, -1, -1]  
누적: \[0, 1, 2, 2, 1, 0]

- 시간 복잡도
구간 갱신: 구간당 O(1)
복원: 한 번의 누적으로 O(N)
전체: O(구간 수 + N). 구간마다 N칸을 더하면 O(구간 수 × N)이라 크게 줄어듭니다.
