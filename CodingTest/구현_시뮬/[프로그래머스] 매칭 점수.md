# [매칭 점수](https://school.programmers.co.kr/learn/courses/30/lessons/42893)

## 문제 설명
프렌즈 대학교 조교였던 제이지는 허드렛일만 시키는 네오 학과장님의 마수에서 벗어나, 카카오에 입사하게 되었다.
평소에 관심있어하던 검색에 마침 결원이 발생하여, 검색개발팀에 편입될 수 있었고, 대망의 첫 프로젝트를 맡게 되었다.
그 프로젝트는 검색어에 가장 잘 맞는 웹페이지를 보여주기 위해 아래와 같은 규칙으로 검색어에 대한 웹페이지의 매칭점수를 계산 하는 것이었다.

- 한 웹페이지에 대해서 기본점수, 외부 링크 수, 링크점수, 그리고 매칭점수를 구할 수 있다.
- 한 웹페이지의 기본점수는 해당 웹페이지의 텍스트 중, 검색어가 등장하는 횟수이다. (대소문자 무시)
- 한 웹페이지의 외부 링크 수는 해당 웹페이지에서 다른 외부 페이지로 연결된 링크의 개수이다.
- 한 웹페이지의 링크점수는 해당 웹페이지로 링크가 걸린 다른 웹페이지의 기본점수 ÷ 외부 링크 수의 총합이다.
- 한 웹페이지의 매칭점수는 기본점수와 링크점수의 합으로 계산한다.

예를 들어, 다음과 같이 A, B, C 세 개의 웹페이지가 있고, 검색어가 hi라고 하자.

<img src="https://grepp-programmers.s3.amazonaws.com/files/production/48a36ec7fa/243a621b-f823-4ccd-99f1-2d8d3e14050d.jpg">

이때 A 웹페이지의 매칭점수는 다음과 같이 계산할 수 있다.

- 기본 점수는 각 웹페이지에서 hi가 등장한 횟수이다.
  - A,B,C 웹페이지의 기본점수는 각각 1점, 4점, 9점이다.
- 외부 링크수는 다른 웹페이지로 링크가 걸린 개수이다.
  - A,B,C 웹페이지의 외부 링크 수는 각각 1점, 2점, 3점이다.
- A 웹페이지로 링크가 걸린 페이지는 B와 C가 있다.
  - A 웹페이지의 링크점수는 B의 링크점수 2점(4 ÷ 2)과 C의 링크점수 3점(9 ÷ 3)을 더한 5점이 된다.
- 그러므로, A 웹페이지의 매칭점수는 기본점수 1점 + 링크점수 5점 = 6점이 된다.

검색어 word와 웹페이지의 HTML 목록인 pages가 주어졌을 때, 매칭점수가 가장 높은 웹페이지의 index를 구하라. 만약 그런 웹페이지가 여러 개라면 그중 번호가 가장 작은 것을 구하라.

## 제한사항
- pages는 HTML 형식의 웹페이지가 문자열 형태로 들어있는 배열이고, 길이는 1 이상 20 이하이다.
- 한 웹페이지 문자열의 길이는 1 이상 1,500 이하이다.
- 웹페이지의 index는 pages 배열의 index와 같으며 0부터 시작한다.
- 한 웹페이지의 url은 HTML의 <head> 태그 내에 <meta> 태그의 값으로 주어진다.
  - 예를들어, 아래와 같은 meta tag가 있으면 이 웹페이지의 url은 https://<hi>careers.kakao.com/index 이다.
- 한 웹페이지에서 모든 외부 링크는 의 형태를 가진다.
  - 내에 다른 attribute가 주어지는 경우는 없으며 항상 href로 연결할 사이트의 url만 포함된다.
  - 위의 경우에서 해당 웹페이지는 <hi>https://<hi>careers.kakao.com/index 로 외부링크를 가지고 있다고 볼 수 있다.
- 모든 url은 https:// 로만 시작한다.
- 검색어 word는 하나의 영어 단어로만 주어지며 알파벳 소문자와 대문자로만 이루어져 있다.
- word의 길이는 1 이상 12 이하이다.
- 검색어를 찾을 때, 대소문자 구분은 무시하고 찾는다.
  - 예를들어 검색어가 blind일 때, HTML 내에 Blind라는 단어가 있거나, BLIND라는 단어가 있으면 두 경우 모두 해당된다.
- 검색어는 단어 단위로 비교하며, 단어와 완전히 일치하는 경우에만 기본 점수에 반영한다.
  - 단어는 알파벳을 제외한 다른 모든 문자로 구분한다.
  - 예를들어 검색어가 "aba" 일 때, "abab abababa"는 단어 단위로 일치하는게 없으니, 기본 점수는 0점이 된다.
  - 만약 검색어가 "aba" 라면, "aba@aba aba"는 단어 단위로 세개가 일치하므로, 기본 점수는 3점이다.
- 결과를 돌려줄때, 동일한 매칭점수를 가진 웹페이지가 여러 개라면 그중 index 번호가 가장 작은 것를 리턴한다
  - 즉, 웹페이지가 세개이고, 각각 매칭점수가 3,1,3 이라면 제일 적은 index 번호인 0을 리턴하면 된다.

## ver1. 문자열 파싱 + 해시맵 기반 링크 점수 분배
```c++
#include <string>
#include <sstream>
#include <regex>
#include <vector>
#include <unordered_map>
#include <algorithm>

using namespace std;

struct info
{
    double basic=0, link=0;
    vector<string> vLink;
    
    double mat(){return basic+link;}
    double score()
    {
        if(vLink.empty()) return 0;
        return basic/(double)vLink.size();
    }
};

const string url="<meta property=\"og:url\"";
const string https="https://";
const string href="<a href=\"";
const char c='\"';

int solution(string word, vector<string> pages) {
    const regex re("[^a-z]");
    transform(word.begin(), word.end(), word.begin(), ::tolower);

    unordered_map<string, info> um;
    vector<string> vHead(pages.size());
    string tmp;
    for(int i=0, s,e; i<pages.size(); i++)
    {
        s=pages[i].find(url);
        s=pages[i].find(https, s);
        e=pages[i].find(c, s);
        vHead[i] = pages[i].substr(s, e-s);
        um.insert({vHead[i], info()});
        
        while(true)
        {
            s=pages[i].find(href,e);
            if(s==string::npos) break;
            s+=href.length();  
            e=pages[i].find(c, s);
            tmp=pages[i].substr(s, e-s);
            um[vHead[i]].vLink.push_back(tmp);          
        }
        
        transform(pages[i].begin(), pages[i].end(), pages[i].begin(), ::tolower);
        pages[i]=regex_replace(pages[i], re, " ");
        stringstream ss(pages[i]);
        while(ss>>tmp)
            if(tmp==word) um[vHead[i]].basic+=1;
    }
    
    for(auto &[h,b]:um)
        for(const string &add:b.vLink)
            if(um.find(add)!=um.end())
                um[add].link+=b.score();
        
    int answer = 0;
    double score=0, cur;
    const double eps=1e-9;
    for(int i=0; i<vHead.size(); i++)
    {
        cur=um[vHead[i]].mat();
        if(score+eps<cur)
        {
            score=cur;
            answer=i;
        }
    }
    
    return answer;
}
```
### 시간복잡도
- 페이지 파싱(find, 소문자 변환, 정규식 치환, 토큰 분리) = O(N*L)
  - N = 페이지 수
  - L = 페이지 최대 길이
- 링크 점수 분배 = O(N*K) (map 조회는 평균O(1), URL 길이를 상수로 봄)
  - K = 페이지당 최대 링크 수
- 최대 점수 탐색 = O(N)
- = O(N*L) = 최악 20 * 1500 = 30000 

### 동작 원리
- 전처리: 검색어 word를 소문자로 변환
- 페이지별 파싱
  - <meta property="og:url" 이후 첫 https://부터 닫는 따옴표까지를 해당 페이지의 URL(vHead[i])로 읽고, unordered_map에 info를 등록
  - 원문에서 <a href=" 패턴을 반복 탐색해 외부 링크 URL을 vLink에 저장
  - 페이지 전체를 소문자로 바꾸고, 정규식 \[^a-z]를 공백으로 치환한 뒤 stringstream으로 토큰을 분리합니다. 토큰이 word와 같으면 basic을 1 증가시킵니다.
- 링크 점수 분배: 각 페이지의 링크 점수는 basic/외부 링크 수. 모든 페이지 돌면서 이 페이지가 가리키는 URL이 입력에 존재하면 해당 페이지의 link에 이 값을 더함
- 정답 선택: 인덱스 순서로 basic + link(매칭점수)가 최대인 페이지 고름. score+epa<cur 일 때만 갱신하므로 동점이면 작은 인덱스 유지

### 문제점
- 정규식 사용: regex_replace 느림. 직접 문자 순회가 효과적

  - idx는 URL → 페이지 인덱스 매핑만담당

  - 페이지 전체를 소문자로 변환한 사본 p를 만듦

- 정답 선택: 인덱스 순으로 basic+link를 보며, best+eps<cur일 때만 갱신 (동점이면 작은 인덱스 유지)

  - 수학적으로는 둘 모두 2점이므로, 인덱스 작은쪽이 정답
  - 하지만 A의 실제값이 1.99...98이나 2.00..04 처럼 저장될 수 있음
- 엄격 비교(score < cur)만 쓰면 오팡이 생김
  - 인덱스가 작은 페이지가 2.0, 큰 페이지가 2.00..04로 계산되면 큰 인덱스가 "더 크다"고 판정되어 답이 뒤집힘
  - 이 문제는 동점이면 작은 인덱스를 답으로 하므로, 오차 떄문에 순위가 바뀌면 오답
- eps로 "오차 범위 안은 같다"고 처리
  -  if(score+eps < cur)
  -  차이가 1e-9보다 작으면 같은 값으로 보고 갱신하지 않음
  -  인덱스 순서로 순회하므로, 같은 값이면 먼저 나온 작은 인덱스가 그대로 유지
-  eps 크기
  - 점수는 정수 개수를 정수로 나눈 값의 합이라 서로 다른 점수의 실제 차이는 1e-9보다 훨씬 크므로, 1e-9정도면 오차는 흡수하고, 실제 차이는 구분함
