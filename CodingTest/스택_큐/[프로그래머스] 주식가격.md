# [주식가격](https://school.programmers.co.kr/learn/courses/30/lessons/42584)

## 문제 설명
초 단위로 기록된 주식가격이 담긴 배열 prices가 매개변수로 주어질 때, 가격이 떨어지지 않은 기간은 몇 초인지를 return 하도록 solution 함수를 완성하세요.  

## 제한사항
prices의 각 가격은 1 이상 10,000 이하인 자연수입니다.  
prices의 길이는 2 이상 100,000 이하입니다.  

## 입출력 예  
|prices|return|
|---|---|
|\[1, 2, 3, 2, 3\]|\[4, 3, 1, 1, 0\]|

### 입출력 예 설명
1초 시점의 ₩1은 끝까지 가격이 떨어지지 않았습니다.
2초 시점의 ₩2은 끝까지 가격이 떨어지지 않았습니다.
3초 시점의 ₩3은 1초뒤에 가격이 떨어집니다. 따라서 1초간 가격이 떨어지지 않은 것으로 봅니다.
4초 시점의 ₩2은 1초간 가격이 떨어지지 않았습니다.
5초 시점의 ₩3은 0초간 가격이 떨어지지 않았습니다.

### ver1. 순회하면서 떨어지는 시간 체크
```
vector<int> solution(vector<int> prices) {
    vector<int> answer((int)prices.size(), 0);
    
    for(int i=0, cnt; i<prices.size()-1; i++)
    {
        for(int j=i+1; j<prices.size(); j++)
        {
            answer[i]++;
            if(prices[j]<prices[i]) 
                break;
        }
    }
    
    return answer;
}
```
시간복잡도: O(n^2) 부르트포스  
로직은 직관적이고 이해하기 쉬움  
문제점: 최악의 경우(가격이 계속 오르기만 하는 경우) 모든 i마다 끝까지 순회 → O(n²)  
마지막 원소(prices.size()-1)는 루프 조건 때문에 아예 처리가 안 되지만, answer가 0으로 초기화돼 있어서 결과적으로 맞음 (마지막 값은 항상 0초이므로)  

### ver2. 스택에 인덱스 저장 후 top의 인덱스와 비
```
vector<int> solution(vector<int> prices) {
    vector<int> answer(prices.size(), 0);
    stack<int> st;
    for(int i=0; i<prices.size(); i++)
    {
        for(;!st.empty() && prices[st.top()]>prices[i]; st.pop())
            answer[st.top()] = i-st.top();
        st.push(i);
    }
    
    for(int i=0; i<answer.size()-1; i++)
        if(answer[i]==0)
            answer[i] = answer.size() - i - 1;
    
    return answer;
}
```
시간복잡도: O(n)
스택에 "아직 가격이 안 떨어진" 인덱스들을 유지  
새 가격이 스택 top의 가격보다 낮으면, top을 pop하면서 그 인덱스의 답을 현재 인덱스 - top 인덱스로 확정  
각 인덱스는 스택에 정확히 한 번 push, 한 번 pop → 전체 O(n)  
스택에 끝까지 안 빠지고 남아있는 인덱스들(즉, 끝까지 가격이 안 떨어진 경우)은 answer가 0으로 남는데, 이를 뒤에서 answer.size() - i - 1로 보정  
* 여기서 answer[i]==0으로 판단하는 방식이 살짝 위험합니다. 
만약 실제 정답이 0인 경우(바로 다음 초에 가격이 떨어지는 경우)와 "스택에 남아서 처리 안 된 경우"를 구분 못 할 수 있는데, 
다행히 스택 로직 상 pop될 때 i-st.top()은 항상 1 이상이라 answer[i]==0은 오직 "스택에 끝까지 남은 경우"에만 발생

#### Monotonic Stack

가격이 떨어질 때까지 기다리는 문제는 Stack을 이용해 아직 답을 모르는 인덱스들을 관리한다.  
이러한 형태를 Monotonic Stack(단조 스택) 패턴이라고 한다.
