# [충돌위험 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/340211)

## 문제 설명
어떤 물류 센터는 로봇을 이용한 자동 운송 시스템을 운영합니다. 운송 시스템이 작동하는 규칙은 다음과 같습니다.

1. 물류 센터에는 (r, c)와 같이 2차원 좌표로 나타낼 수 있는 n개의 포인트가 존재합니다. 각 포인트는 1~n까지의 서로 다른 번호를 가집니다.
2. 로봇마다 정해진 운송 경로가 존재합니다. 운송 경로는 m개의 포인트로 구성되고 로봇은 첫 포인트에서 시작해 할당된 포인트를 순서대로 방문합니다.
3. 운송 시스템에 사용되는 로봇은 x대이고, 모든 로봇은 0초에 동시에 출발합니다. 로봇은 1초마다 r 좌표와 c 좌표 중 하나가 1만큼 감소하거나 증가한 좌표로 이동할 수 있습니다.
4. 다음 포인트로 이동할 때는 항상 최단 경로로 이동하며 최단 경로가 여러 가지일 경우, r 좌표가 변하는 이동을 c 좌표가 변하는 이동보다 먼저 합니다.
5. 마지막 포인트에 도착한 로봇은 운송을 마치고 물류 센터를 벗어납니다. 로봇이 물류 센터를 벗어나는 경로는 고려하지 않습니다.

**이동 중 같은 좌표에 로봇이 2대 이상 모인다면 충돌할 가능성이 있는 위험 상황으로 판단합니다.**  
관리자인 당신은 현재 설정대로 로봇이 움직일 때 위험한 상황이 총 몇 번 일어나는지 알고 싶습니다. 만약 어떤 시간에 여러 좌표에서 위험 상황이 발생한다면 그 횟수를 모두 더합니다.

운송 포인트 n개의 좌표를 담은 2차원 정수 배열 points와 로봇 x대의 운송 경로를 담은 2차원 정수 배열 routes가 매개변수로 주어집니다. 
이때 모든 로봇이 운송을 마칠 때까지 발생하는 위험한 상황의 횟수를 return 하도록 solution 함수를 완성해 주세요.

## 제한사항
- 2 ≤ points의 길이 = n ≤ 100
  - points[i]는 i + 1번 포인트의 [r 좌표, c 좌표]를 나타내는 길이가 2인 정수 배열입니다.
  - 1 ≤ r ≤ 100
  - 1 ≤ c ≤ 100
  - 같은 좌표에 여러 포인트가 존재하는 입력은 주어지지 않습니다.
- 2 ≤ routes의 길이 = 로봇의 수 = x ≤ 100
  - 2 ≤ routes[i]의 길이 = m ≤ 100
  - routes[i]는 i + 1번째 로봇의 운송경로를 나타냅니다. routes[i]의 길이는 모두 같습니다.
  - routes[i][j]는 i + 1번째 로봇이 j + 1번째로 방문하는 포인트 번호를 나타냅니다.
  - 같은 포인트를 연속으로 방문하는 입력은 주어지지 않습니다.
  - 1 ≤ routes[i][j] ≤ n

## 입출력 예
|points|routes|result|
|----------|-------|--|
|\[\[3, 2], \[6, 4], \[4, 7], \[1, 4]]|\[\[4, 2], \[1, 3], \[2, 4]]|1|
|\[\[3, 2], \[6, 4], \[4, 7], \[1, 4]]|\[\[4, 2], \[1, 3], \[4, 2], \[4, 3]]|9|
|\[\[2, 2], \[2, 3], \[2, 7], \[6, 6], \[5, 2]]|\[\[2, 3, 4, 5], \[1, 3, 4, 5]]|0|

## ver1. Queue + Class
```
const int MAX=101;
vector<vector<int>> cnt(MAX, vector<int>(MAX, 0));
class robot
{
public:
    int r, c;
    vector<pair<int,int>> route;
    int dest=0;
    
    robot(){}
    robot(const vector<vector<int>> &p, const vector<int> &v)
    {
        for(int i=0, y, x; i<v.size(); i++)
        {
            y=p[v[i]-1][0], x=p[v[i]-1][1]; 
            route.push_back({y,x});
        }
        r=route.front().first, c=route.front().second;
        cnt[r][c]++;
    }
    
    bool move()
    {
        cnt[r][c]--;
        if(dest>=route.size()) return false;
        
        int y=route[dest].first, x=route[dest].second;
        if(y!=r) r+=y>r?1:-1;
        else if(x!=c) c+=x>c?1:-1;
        
        cnt[r][c]++;
        if(y==r && x==c) dest++;
        
        return true;
    }
};

int crush(set<pair<int,int>> &s)
{
    int c=0;
    for(auto it=s.begin(); it!=s.end(); ++it)
        if(cnt[it->first][it->second]>1) c++;
    s.clear();
    return c;
}

int solution(vector<vector<int>> points, vector<vector<int>> routes) {
    
    queue<robot> q;
    set<pair<int,int>> s;
    int answer = 0;
    for(int i=0; i<routes.size(); i++)
    {
        q.push(robot(points, routes[i]));
        s.insert({q.back().r, q.back().c});
    }
    
    robot tmp;
    while(!q.empty())
    {
        int size=q.size();
        for(int i=0; i<size; i++)
        {
            tmp = q.front(), q.pop();
            if(tmp.move()) 
            {
                s.insert({tmp.r,tmp.c});
                q.push(tmp);
            }
        }
        
        answer+=crush(s);
    }
    
    return answer;
}
```
### 시간복잡도
- T = 모든 로봇의 총 이동 스텝 수의 합
  - 최악: x개 로봇 * m개 구간 * 구간 당 최대 거리 200)
  - 로봇 하나 당 처리 O(m)
- 전체 = O(T * m) = 100(로봇) * 100(구간) * 200(거리) * 100(route 길이) = 2 * 10^8

### 동작 원리
- 각 로봇을 robot 객체(좌표 r,c + 자기 경로 전체 route + 다음 목표 인덱스 dest)로 만들어 큐에 넣음
- route\[0]이 시작점 자체이므로, 첫 tick은 실제 이동 없이 dest만 0 → 1
  - 0초 시점 충돌 체크
- while(!q.empty()) 바깥루프 = 시간(틱), 안쪽 for(i=0; i<size; i++) = 이번 틱에 존재하는 로봇 한번씩 처리
- 로봇을 pop → move() 한 칸 이동(r축 소진 후 c축) → 남아 있으면 push 도착하면 버림
- 매 틱 끝나고 crush(s)로 그 틱에 좌표가 겹친 지점(전역 cnt 배열 참조) 개수를 셈
- 로봇이 사라질 때 cnt 증감이 정확히 상쇄되게 설계되어 있어서, 완주하면 자동으로 0으로 복귀 

### 문제점
- 버그 유발 쉬운 구조
  - 라운드 경계를 큐의 동적 크기에 의존하다 보니 q.size()를 매 반복 재평가하면 라운드 도중 완료된 로봇 때문에 동기화 깨지는 버그 발생
- 매 틱 로봇 객체(경로 벡터 포함) 전체 복사
  - 불필요한 힙 할당/해제 반복 = 상수 배 큼
- 0초 체크를 **첫 틱이 우연히 헛이동이라 대신 처리됨**이라는 암묵적 트릭에 의존
  - 코드만 보고 의도 파악 어려움(주석 남겨야 유지 보수 가능)
- robot tmp: 하나를 밖에 선언해 재사용 의미 없음 (대입 시 복사 발생)

## ver+. 배열 기반
```
int solution(vector<vector<int>> points, vector<vector<int>> routes) {
    int x = routes.size();
    int m = routes[0].size();

    vector<int> r(x), c(x), idx(x, 1);
    vector<bool> active(x, true); // 이번 틱 위치가 충돌 판정 대상인가

    for (int i = 0; i < x; i++) {
        auto &p = points[routes[i][0]-1];
        r[i] = p[0]; c[i] = p[1];
    }

    auto countCollisions = [&]() {
        map<pair<int,int>,int> cnt;
        for (int i = 0; i < x; i++)
            if (active[i]) cnt[{r[i], c[i]}]++;
        int res = 0;
        for (auto &kv : cnt) if (kv.second > 1) res++;
        return res;
    };

    int answer = countCollisions(); // 0초 시점 체크

    int finished = 0;
    while (finished < x) {
        for (int i = 0; i < x; i++) {
            if (!active[i]) continue;      // 이미 지난 틱에 완료 -> 더 이상 이동 없음
            auto &t = points[routes[i][idx[i]]-1];
            if (r[i] != t[0]) r[i] += (t[0] > r[i] ? 1 : -1);
            else if (c[i] != t[1]) c[i] += (t[1] > c[i] ? 1 : -1);

            if (r[i] == t[0] && c[i] == t[1]) {
                idx[i]++;
                if (idx[i] == m) finished++; // 마지막 포인트 도착: 이번 틱까지는 충돌 판정에 포함
            }
        }
        answer += countCollisions();

        for (int i = 0; i < x; i++)
            if (idx[i] == m) active[i] = false; // 다음 틱부터 제외
    }

    return answer;
}
```
### 시간복잡도
- 틱마다 전체 로봇을 O(x)로 훑되, 매 이동은 정수 몇개 갱신뿐이라 로봇당 스텝 처리 비용 = O(1) (복사/할당 없음)
- 전체 = O(T) (T = 총 이동 스텝 수 - 원본 대비 m배 정도 빠름) 

### 동작 원리
- 로봇 상태를 개체가 아니라 병렬 배열 r\[i], c\[i], idx\[i], active\[i]로 표현
  - routes / points는 참조만
- 루프 진입 전에 countCollisions()를 한 번 호출에 명시적으로 0초 체크
- while(finished < x)가 바깥(틱) 루프, 안쪽 for(i=0;i<x;i++)가 모든 로봇을 훑되 active\[i]==false인 완료 로봇은 skip
- 이번 틱에 마지막 포인트 도착한 로봇은 finished++만 하고, 이번 틱의 충돌 판정에는 포함시킨 뒤, 라운드가 끝난 다음에 active\[i]=false로 꺼서 다음 틱부터 제외
- 라운드 경계가 배열 인덱스 0..x-1 고정 범위라서 원본에서 터진 종류의 **루프 도중 크기 변함** 버그가 구조적으로 생길 수 없음
