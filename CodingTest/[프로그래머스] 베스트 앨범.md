# [베스트 앨범](https://school.programmers.co.kr/learn/courses/30/lessons/42579)

## 문제 설명
스트리밍 사이트에서 장르 별로 가장 많이 재생된 노래를 두 개씩 모아 베스트 앨범을 출시하려 합니다. 노래는 고유 번호로 구분하며, 노래를 수록하는 기준은 다음과 같습니다.  
  
속한 노래가 많이 재생된 장르를 먼저 수록합니다.  
장르 내에서 많이 재생된 노래를 먼저 수록합니다.  
장르 내에서 재생 횟수가 같은 노래 중에서는 고유 번호가 낮은 노래를 먼저 수록합니다.  
노래의 장르를 나타내는 문자열 배열 genres와 노래별 재생 횟수를 나타내는 정수 배열 plays가 주어질 때, 베스트 앨범에 들어갈 노래의 고유 번호를 순서대로 return 하도록 solution 함수를 완성하세요.  
  
## 제한사항
genres\[i\]는 고유번호가 i인 노래의 장르입니다.  
plays\[i\]는 고유번호가 i인 노래가 재생된 횟수입니다.  
genres와 plays의 길이는 같으며, 이는 1 이상 10,000 이하입니다.  
장르 종류는 100개 미만입니다.  
장르에 속한 곡이 하나라면, 하나의 곡만 선택합니다.  
모든 장르는 재생된 횟수가 다릅니다.  

### 입출력 예
|genres|plays|return|
|---|---|---|
|\["classic", "pop", "classic", "classic", "pop"\]|\[500, 600, 150, 800, 2500\]|\[4, 1, 3, 0\]|

### 입출력 예 설명
classic 장르는 1,450회 재생되었으며, classic 노래는 다음과 같습니다.   
- 고유 번호 3: 800회 재생  
- 고유 번호 0: 500회 재생  
- 고유 번호 2: 150회 재생
  
pop 장르는 3,100회 재생되었으며, pop 노래는 다음과 같습니다.  
- 고유 번호 4: 2,500회 재생    
- 고유 번호 1: 600회 재생
  
따라서 pop 장르의 \[4, 1\]번 노래를 먼저, classic 장르의 \[3, 0\]번 노래를 그다음에 수록합니다.  
  
장르 별로 가장 많이 재생된 노래를 최대 두 개까지 모아 베스트 앨범을 출시하므로 2번 노래는 수록되지 않습니다.  

### ver1. unordered_map & sort
```
struct st
{
    public:
    int id;
    int n;
    
    st(int idx, int num)
    {
        id = idx;
        n = num;
    }
};

vector<int> solution(vector<string> genres, vector<int> plays) {
    const int M=2;
    
    unordered_map<string, vector<st>> info;
    unordered_map<string, int> sum;
    for(int i=0; i<plays.size(); i++)
    {
        info[genres[i]].push_back(st(i, plays[i]));
        sum[genres[i]] += plays[i];
    }
    
    vector<string> order;
    for(auto it=sum.begin(); it!=sum.end(); ++it)
        order.push_back(it->first);
    
    sort(order.begin(), order.end(), [&](string &a, string &b){
        return sum[a]>sum[b];
    });
    
    vector<int> answer;
    for(int i=0; i<order.size(); i++)
    {
        vector<st> v = info[order[i]];
        sort(v.begin(), v.end(), [](st &s1, st &s2){
           return s1.n > s2.n; 
        });
        
        int n = min(M, (int)v.size());  
        for(int j=0; j<n; j++)
            answer.push_back(v[j].id);
    }
    
    return answer;
}
```
##### 캡처란?
람다 안에서 람다 바깥에 있는 지역 변수를 쓰려면, 그 변수를 어떻게 가져올지 캡처 목록에 명시해야 합니다.  
```
[캡처방법](매개변수) { 본문 }
```
\[\] : 아무것도 캡처 안 함 → 바깥의 지역 변수를 람다 안에서 못 씀
\[&\] : 바깥 변수를 참조로 캡처 (전부 다)
\[=\] : 바깥 변수를 값 복사로 캡처 (전부 다)
\[&sum\] : sum만 참조로 캡처
\[sum\] : sum만 값 복사로 캡처

#### 개선점
1. 불필요한 복사
```
vector<st> v = info[order[i]];   // 매번 벡터 전체를 복사
```
참조로 받으면 복사 비용을 없앨 수 있어요.
```
auto &v = info[order[i]];   // 복사 없이 참조
```
2. stable_sort 대신 partial_sort (선택)
각 장르에서 필요한 건 상위 2곡뿐인데 전체를 정렬하고 있어요. 장르당 곡 수가 많아질 경우를 대비하면 partial_sort가 이론적으로 더 효율적입니다. 다만 동률 처리(안정성)가 깨지므로, 동률일 때 index 순서를 비교자에 직접 넣어야 해요.  
```
int n = min(M, (int)v.size());
partial_sort(v.begin(), v.begin() + n, v.end(), [](const st &s1, const st &s2){
    if (s1.n != s2.n) return s1.n > s2.n;
    return s1.id < s2.id;   // 동률이면 인덱스 작은 순
});
```
이렇게 하면 stable_sort 없이도 동률 처리가 되고, 상위 n개만 정렬하면 되니 이론적으로 더 빠릅니다. (이 문제는 제약조건상 데이터 크기가 작아 성능 차이는 미미하지만, 습관으로는 좋습니다.)  
3. struct st → pair<int,int>로 단순화 가능
굳이 구조체를 만들 필요 없이 pair<int, int> (재생수, 인덱스) 형태로 넣으면 STL이 기본 제공하는 비교 연산을 활용할 수 있어 코드가 짧아져요.
